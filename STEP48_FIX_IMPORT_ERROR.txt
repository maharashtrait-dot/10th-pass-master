Root cause:
The bundled GET importer used a PostgreSQL query where a parameter could be left with an ambiguous type on some local database schemas. Also, one row error aborted the transaction, causing all later rows to fail.

Fix:
1. Explicit PostgreSQL casts are used for chapter-number/name parameters.
2. Every row uses its own SAVEPOINT, so one bad row cannot abort all remaining imports.
3. The importer still verifies the official 2024 Mathematics-I March English package and marks successful rows as ACTUAL_PYQ + pyq_verified=TRUE.
4. Admin cache bumped to v48.
